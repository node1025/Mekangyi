# 고객몰·관리자·API 분리 배포

고객 화면과 관리자 화면은 각각 빌드한 정적 파일을 Nginx가 제공하고, 회원·주문 같은 데이터 요청만 같은 서버의 Express API로 넘깁니다. API와 MariaDB는 루프백에서만 받습니다.

## 준비

서로 다른 고객·관리자 도메인, 각 도메인용 TLS 인증서, 실제 사내망 또는 VPN의 허용 IP, Node.js 22.12 이상, MariaDB 11.4, Nginx가 필요합니다. 이 구성은 인증서나 VPN을 발급·생성하지 않습니다.

- 고객 Nginx: `client/dist`와 상품 사진. 고객용 도메인
- 관리자 Nginx: `admin/dist`와 상품 사진. 관리자용 도메인, IP 허용 목록 적용
- API: `server`, `127.0.0.1:5000`. 외부 포트는 열지 않음
- MariaDB: `127.0.0.1:3306`. 외부 포트는 열지 않음

고객·관리자 도메인을 다르게 사용해 쿠키와 브라우저 저장소를 분리합니다. 같은 도메인의 포트만 바꾸는 운영 방식은 사용하지 않습니다.

## 설정 순서

1. `server/.env.example`을 `server/.env`로 복사합니다. DB 비밀번호와 URL 인코딩한 비밀번호를 포함한 `MARIADB_URI`, 서로 다른 JWT 비밀값, 두 사이트의 정확한 HTTPS origin(`FRONTEND_URL`, `ADMIN_FRONTEND_URL`)을 설정합니다. `TRUSTED_PROXIES`와 `ADMIN_GATEWAY_PEERS`는 이 서버의 Nginx 주소인 `127.0.0.1,::1`을 유지합니다. `RESET_MAIL_MODE`는 `smtp`로 두고 SMTP 값을 넣습니다. 예시 문자열을 실제 운영 비밀값으로 교체합니다.
2. 고객·관리자 정적 파일을 만듭니다.

```sh
npm ci
npm run build
```

3. 고객용 Nginx에는 `deploy/nginx/shop.conf`와 `deploy/nginx/proxy.conf`를 적용합니다. 관리자용 Nginx에는 `deploy/nginx/admin.conf`, `deploy/nginx/proxy.conf`, `deploy/nginx/admin-allowlist.conf`를 적용합니다. 설정 안의 `/srv/site`에 각각 `client/dist`, `admin/dist`를 두고, `/srv/uploads`는 `server/uploads`를 읽기 전용으로 연결합니다. 인증서는 설정에 적힌 `/etc/nginx/certs/fullchain.pem`, `privkey.pem` 위치에 둡니다. 개인키는 소스 관리나 공유 ZIP에 넣지 않습니다.
4. `deploy/nginx/admin-allowlist.conf`에 실제 사내망 또는 VPN의 출구 IP나 대역을 `allow`로 추가합니다. 마지막 `deny all;`은 유지합니다. 예시 IP는 작동하는 실제 회사 주소가 아닙니다. 기본 허용은 루프백뿐입니다.
5. 고객 도메인을 고객 Nginx로 연결합니다. 관리자 도메인은 사내 DNS 또는 VPN에서만 해석·접속되게 하고, 관리자 Nginx는 그 사설 또는 VPN 주소에서만 받습니다. API의 `HOST`는 비워 두어 `127.0.0.1`에만 열리게 합니다.
6. API를 실행하는 계정이 `server/uploads`에 쓸 수 있어야 합니다. 기존 사진과 업로드 파일은 유지합니다.

```sh
npm run db:init
npm run seed:demo
npm run admin:demo
```

API는 `server`에서 `node src/app.js`로 실행합니다. 관리자 생성 명령은 신규 `demoAdmin` 계정과 임의의 비밀번호를 터미널에 한 번 표시합니다. 기존 계정의 비밀번호·권한은 바꾸지 않습니다. 샘플 데이터는 `_demo`로 끝나는 DB에만 넣습니다. 기존 운영 DB를 초기화하거나 덮어쓰지 않습니다.

결제·메일 값이 필요하면 `server/.env`에 해당 비밀값을 넣습니다. 현재 샘플은 외부 연동 키를 포함하지 않습니다.

앞단에 로드밸런서가 있다면 Nginx가 보는 주소는 그 장비의 주소가 됩니다. 모든 전달 헤더를 믿지 말고, 실제 네트워크 경계에 맞춰 real-IP 신뢰 대역을 따로 정합니다. 현재 설정은 Nginx가 브라우저와 직접 연결되는 구조입니다.

## 배포 후 확인

- 고객 주소에서 `/`, 캐러셀, 상품 사진 및 `/api/products`가 동작하는지 확인합니다.
- 고객 주소의 `/admin`은 404, `/api/admin/session`·관리자 주문 조회·상품 PATCH는 403이어야 합니다.
- 허용 IP에서는 관리자 로그인 페이지가 열리고, 비허용 IP에서는 로그인·JS·이미지·API 모두 403이어야 합니다.
- 일반 회원·로그인 전 계정은 관리 API를 사용할 수 없어야 합니다. 관리자는 로그인 후 다시 비밀번호를 확인해야 합니다.
- 관리자가 가격을 변경한 뒤 고객 목록·상세의 재조회에 같은 가격이 나타나는지 확인합니다.
- TLS 인증서의 도메인과 유효기간, 업로드 쓰기 권한, DB 백업과 복구를 운영 환경에서 확인합니다.

```sh
nginx -t
```
