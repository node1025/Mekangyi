# 관리자 URL·도메인 강화

보안은 **IP 허용 목록 + 1·2차 비밀번호**가 핵심입니다. 아래는 주소를 추측하기 어렵게 하는 **추가** 설정입니다.

## 1. 도메인(호스트)

- 고객몰과 **다른 호스트**만 사용 (`deploy/nginx/admin.conf`).
- `admin.example.com` 대신 사내 DNS에만 있는 이름 예:
  - `ops-7f3a9c2.internal.bukangi.shop`
- `admin-allowlist.conf`에 **VPN·사무실 egress IP**만 `allow` 후 `deny all`.

## 2. 경로(프론트 빌드)

프로젝트 루트:

```bash
npm run admin:route-slug
# admin/.env 자동 반영:
npm run admin:route-slug -- --write
npm run build
```

`admin/.env` 예:

```env
VITE_ADMIN_ROUTE_ROOT=/bk-ops-7f3a9c2e
```

빌드 후 실제 URL:

| 단계 | 경로 |
|------|------|
| 1차 로그인 | `https://(관리자호스트)/bk-ops-7f3a9c2e/sign-in` |
| 2차 재인증 | `.../bk-ops-7f3a9c2e/verify` |
| 콘솔 | `.../bk-ops-7f3a9c2e/desk` |

`VITE_ADMIN_ROUTE_ROOT`를 비우면 로컬 개발용 기본 경로(`/login`, `/admin`)를 유지합니다.

`server/.env`의 `ADMIN_FRONTEND_URL`은 관리자 **최종 입장 URL**(콘솔 또는 verify)을 기준으로 맞춥니다.

## 3. 로컬(VS Code)

기본은 `http://localhost:9081/login` 그대로 사용 가능합니다.  
운영과 동일 경로로 테스트하려면 `admin/.env`에 `VITE_ADMIN_ROUTE_ROOT` 설정 후 **Build admin**·스택 재시작.
